# 持续活动与 Bilibili 接入

实现日期：2026-10-29。实现计划见 [ACTIVITY_AND_APPS_PLAN.md](ACTIVITY_AND_APPS_PLAN.md)。

## 活动与模型输入

仍使用官方 `deepseek-harness-sdk==0.2.1rc2`，同一个持久 Session 与原生 schedule/skill/web 工具。没有第二套主体循环。

- 运行回合的原 `activity_id` 不变。`life_activities` 保存 `logical_activity_id`，`activity_runs` 保存映射。
- `world_activity` 查询或更新实际继续意图与已观察引用。`world_pause` 等待明确 App 范围或时间点，最长一小时；到期安静放下，不设持久提醒、不唤醒模型确认。
- 额度耗尽、崩溃是 suspended，下次合法事件或日程机会可以继续。普通完成或 `world_finish` 放下。新通知只在步骤间送达，不取消在途写入。
- preamble 的活动限次使用逻辑活动 ID；目标消息防重不变。
- 已结束活动先归档真实观察、动作和回执，再在本地生成带来源引用的事实索引，或复用已有有效简述；不再独立调用摘要模型。归档、JSON、来源或索引失败均保留原历史。
- 采用真实 SDK 的 `Session.append(... surfaceOp: replace ...)` 持久替换，不修改 JSONL、不篡改冻结请求。替换范围按当前 surface 顺序计算，包含所有被覆盖节点，保留工具调用/结果配对。
- 最近简述由 World 每次 runtime 状态提供，默认10条，可配置；不会递归生成无限增长的全局总摘要。DSH 长活动压缩排除过时 runtime 与已结束活动简述，仍保留原始日志。
- `var/experience/activities/<id>/` 包含 `events.jsonl`、校验清单与 `summary.json`；World SQLite 保存索引。`world_recall` 支持活动、App、时间、关键词、分页和原文读取。更早档案保留。

### 2026-10-29 最新规则：取消独立付费摘要

用户核对账单后授权取消独立的模型摘要调用。`dsh/activities.mjs` 不再持有摘要prompt或调用 `ctx.llm.stream`，只请求本地 `activity_index`；普通结束、旧记录迁移、维护和失败恢复使用同一入口。长活动的原生压力压缩继续保留，不能将其与活动结束后的额外摘要混为一谈。

`activity_index.py` 从该活动实际记录的工具选择和回执生成最小事实：动作、次数、已知对象标识与原回执状态；不扫描App库、不理解未读内容、不复述完整日志、不推断话题或成功。相同调用ID按运行回合分别关联；无回执、unknown、业务不可用与错误明确保留。时间、App及活动编号仍由原索引元数据提供，近期默认10条，空活动仍不占位。

主体可在已有 `world_finish` 调用的可选 `note` 中自愿留一句认为值得记住的信息，无需额外调用、不强制填写。索引用“自留”标记主体文字，并与实际动作/回执分开；自留文字不覆盖未知操作账本、不自动发给任何人、不变成提醒或待办。普通无工具输出仍可结束，不强制回头补写。

完整原始事件、校验清单、合法SDK历史投影及按需检索保留。新索引沿用兼容 `summary.json` v2及来源引用，旧v1/v2有效简述原样复用，不花钱刷新、不删旧文件。已有索引损坏或写盘失败时保留原上下文及旧文件，报告错误，不用付费模型兜底。`refresh_activity_summaries` 和 `--refresh-summaries` 为兼容名称，现在只核验/补齐本地索引并复用已有有效文件。

历史账单、摘要用途分类与费用均保持，不将以前的消耗归零。此项消除独立摘要调用费用，不承诺总费用固定下降多少；主体唤醒/工具循环、视觉和确有需要的长活动压缩仍有各自开销。下文的模型重整与费用验证是之前版本的历史记录，不是当前摘要策略。

### 2026-10-29：常驻活动索引精简（历史实现）

用户要求常驻内容仅保留时间、App、关键信息及活动编号。`recent_activities` 每条现为 `time.start/end`（带时区）、`apps`、`brief`、`logical_activity_id`，以及固定类型标记；不再重复归档URI、来源事件数组或摘要版本。时间和App从实际经历提取，不读取未送达通知、未打开的App正文，也不从模型猜测。

新简述直接从该活动各回合的原始观察、模型输出、选择及回执生成一次，不拼接多段运行摘要、不再次总结旧摘要。正文一般1～3句、80～150字作为写作目标，少量信息允许更短、复杂内容允许更长；没有新增输入预算或机械截断。摘要输入省略重复的SSE传输片段和计费字段，原始输出与完整归档仍保留。

`summary.json` 保存 `version: 2` 及来源事件 `references`，供归档校验与按需回看。旧版本兼容读取；刷新失败保留原简述及原历史。未知写入继续使用独立操作账本，不依赖摘要正文。已有合格v2索引跨重启复用。

需要细节时，`world_recall(activity_id=<logical_activity_id>)` 检索、分页，或加 `full=true` 读取经过校验的完整记录。工具已有此能力，本次仅明确环境说明。

离线重整入口：`tools/migrate_activities.py --refresh-summaries --apply`，仍需显式指定私有数据目录和原工作目录。只运行SDK的只读整理维护，不启动App或主体决策；先备份，在私有副本验证原文校验和、操作账本、Session身份及再次执行幂等后再应用。

已在私有副本上用实际模型从原始经历重整35条旧简述，再仅原子替换正式归档的简述文件。35份完整经历的原始校验和、运行回合映射和Session身份核对通过；原操作账本及3笔未知写入未变。真实整理调用的输入、用量和回执也随迁移保留，未重复计费导入。私有副本重复应用时新增遥测为0。

本次最近10条的正文从7,966降到1,545字符；完整常驻索引由11,942降到3,637字符，均为字符计数，不冒充token数。没有改变保留10条的设置。正式服务已沿用现有启动器恢复live与反向WS。

### 2026-10-29：新通知与空唤醒

唤醒、步骤间通知和 `world_notifications` 默认只领取尚未送达的新通知，最多100条；超出的仍待送达。显式设置 `include_delivered=true` 可以回看已送达且未忽略的通知，旧项不再次创建观察。已送达通知仍可定位打开；QQ会话已读仍由实际阅读推进，Web通知历史查询保持只读。

`activity_policy.py` 使用本地保守规则决定是否需要简述，不增加分类模型调用。只收到/忽略通知、发现工具或查看会话未读概况，随后结束的空回合，只保存完整原始经历，不生成 `summary.json`，也不进入近期活动列表。实际打开消息、搜索、读取App内容、记录明确继续意图、非空主体文本输出、失败或未知结果仍走正常整理；新工具默认视为实际活动，不因没有对外发言就省略。

空回合仍先归档及校验，再通过同一SDK合法历史投影退出可见完整链路。未完成活动、待续意图、失败恢复与未知写入不被裁掉；历史原文可通过活动编号或经历检索读取。旧完成回合首次启动时仅一次分类索引，旧摘要和日志文件保留，重复启动不重写索引、不补调摘要模型。环境不要求星回为了形成活动而去做事。

## 日程与 QQ

用户在查看大量无行动周期唤醒后，明确选择约2～10分钟、按日程调整。`value <= 5` 时不排周期唤醒，否则 `120 + 480 * (1-value/100)^2` 秒；原20+280公式不再作为默认。当前日程value=75时为150秒，value=50时240秒，value=20时约427秒。计时从前次运行完成/挂起开始；活动运行和明确等待时不排心跳积压。等待过期重置空闲计时。固定 `--idle-seconds` 与自适应互斥。真实 @/回复仍按原通知规则处理；管理员、原生提醒独立。

`ASTCHO_WORLD_WAKE_MIN_SECONDS=120`、`ASTCHO_WORLD_WAKE_MAX_SECONDS=600` 或显式 `--wake-min-seconds/--wake-max-seconds` 可调整上下限；命令行优先，修改配置后正常重启。通式为 min+(max-min)*(1-value/100)^2，上下限必须为有限正数且max>=min。它提供空闲机会，不强制读取、发言或创建待办，也不按空回合数量额外退避；明确等待、提醒和通知不使用该间隔。

首轮启用全群普通消息免打扰，新增群默认免打扰；迁移只执行一次，不覆盖后续显式设置。模型主动订阅某群是有时限的单独关注，不修改长期免打扰。

App 新增严格 `ambient_schema`/`ambient_state` 契约，与管理员 `dashboard_state` 分开。QQ 只发布群名、ID、未读和静音状态，不发布正文、最后消息、话题或认知资料。读取通知上下文和直接打开群使用同一个已读水位，早于已显示页的消息仍算已读。

## Bilibili

复用 `c1overzz/dsh-bili-scroll` 提交 `2c7b3f14f525360f8657b102ec453fd8f02baf3a` 的只读能力子集：搜索、推荐、评论读取、封面和故事板帧。源码与 MIT 声明在 `src/astcho_world/vendor/`。未加载其定时值班、独立 agent、日报、人设或评论风格拦截。

直接复用同一个 `bilibili-api-python==17.4.1` 实现扫码登录、带时间戳的分P字幕、点赞/取消、评论/回复、收藏夹增删和查询。独立进程、私有数据及凭证、独立 Python 环境 `var/runtimes/bilibili`；完整依赖锁在 `requirements/bilibili.lock.txt`。安装：

```sh
.venv/bin/python -m venv var/runtimes/bilibili
var/runtimes/bilibili/bin/python -m pip install -r requirements/bilibili.lock.txt
var/runtimes/bilibili/bin/python -m pip install -e . --no-deps
```

推荐分页翻本次缓存，refresh 重新取得推荐。候选信息、字幕、评论、封面和故事板分别标明实际范围。故事板通常仅首P；画面通过共用 ImageReader 交独立视觉模型理解，不宣称文本主体原生看图。当前 ASR 不可用；无字幕明确返回。

B站获取普通链接资源，由主体另调用 QQ `share_link`。支持已知群和已配置管理员主动私聊、可选附言/真实引用；不自制卡片、不伪造管理员来信、不开放普通私聊任务入口。URL 必须已经通过观察出现。QQ 分享保存 URL、目标、文字、真实消息ID和回执，发送消息也进入 QQ 存档以便被引用。

B站互动和 QQ分享使用显式 `intent_id` 区分重试与新意图。同意图跨模型调用ID/重启仍使用一个账本操作；未知回执不重发。新意图才换 ID。没有外部幂等支持时不宣称严格恰好一次。

Web 的 App 控制只开放 manifest 声明的账号工具，管理员扫码、检查登录、退出不算主体经历。账号登录需要人扫码；不在聊天传 Cookie。

## 开关与迁移

- `ASTCHO_WORLD_ACTIVITY_CONTEXT=1`：活动归档及有限简述；`ASTCHO_WORLD_RECENT_ACTIVITIES=10`。
- `ASTCHO_WORLD_ADAPTIVE_WAKE=1`：按日程唤醒。
- `ASTCHO_WORLD_MUTE_GROUPS=1`：一次性已知群静音/新增群默认。
- 配置项 `enabled_env: ASTCHO_WORLD_BILIBILI` 配合环境值0可单独禁用 B站，不删数据。

`tools/migrate_activities.py` 默认预览；`--apply` 只做 Session 维护和只读摘要，不运行 App 动作。先停单个 World、备份 World/QQ/DSH及私有配置，再在私有副本执行，`--workspace` 保留原 Session 的 cwd查找键。旧记录按原回合分组归档并标记为“旧环境运行记录”，不假定原回合就是生活活动。重复执行幂等；仅在全部旧记录已有校验简述时替换旧可见历史。原日志与旧操作身份保留。失败可继续重试，不删除原历史。

回退可关活动投影、日程唤醒、B站三个开关；新增日志仍保留。不要恢复旧进程并发运行，也不要通过重试外部写来验证回退。

2026-10-29 后续：按用户要求补充评论克制、管理员私聊优先和群主动分享保护。近期分享通过QQ元数据和share_context提供；群入口默认600秒间隔、300秒近期上下文及内部受众理由。原聊天规则不变，无每日配额或内容评分，详见 [评论与分享](SHARING_POLICY.md)。

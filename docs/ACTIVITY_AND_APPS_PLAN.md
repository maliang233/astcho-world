# 星回持续活动、经历上下文与 Bilibili App 开发计划

日期：2026-10-29（Asia/Shanghai）

执行对象：GPT-6.1-sol及后续维护者

实施目录：`.`

原版基准：`../astcho-github` 的本地工作区，包含未提交改动

状态：已获用户授权执行。实现及验证记录见 [ACTIVITIES_IMPLEMENTATION.md](ACTIVITIES_IMPLEMENTATION.md)；原计划要求继续作为验收边界。

本计划承接 [原开发计划](DEVELOPMENT_PLAN.md)，以用户随后对主体回复、活动、上下文、唤醒及 B 站的明确讨论为准。原计划中独立 Planner/Replyer 等早期约定已有后续授权变化，不能用旧文档覆盖用户的新要求。仍须遵守 [AGENTS.md](../AGENTS.md)、原 prompt 保护和原项目独立可用要求。

## 1. 用户目标与确定的边界

环境提供选择与行动条件。星回自己选择关注、继续、切换、暂停或放下，不按程序编写的生活流程运行。

本轮后续开发包含四个互相衔接的部分：

1. 持续活动及事件恢复：一段自主活动可以跨模型调用、运行回合及重启。
2. 按活动组织上下文：近期简述常驻，完整经历按需检索，当前活动可以续接。
3. 按日程提供空闲活动机会：普通群免打扰，睡眠不触发周期唤醒。
4. Bilibili App：推荐流、搜索、阅读视频、站内互动，以及经 QQ 自主分享。

必须保持：

- 原项目及受保护的 `src/astcho/**`、`tests/legacy/**`、`docs/legacy-baseline.json` 不改。实施者亲自读取原代码，不用本计划代替原实现。
- 原聊天、视觉 prompt 与人格原文逐字保留。新提示仅属于环境调度、活动简述或 B 站工具说明，不重写原聊天风格。
- 不新增总输入 token 硬上限，不任意截断当前活动的工具调用/结果。用户已同意限制常驻的已结束活动简述数量，此授权不扩展为通用历史剪裁。
- 同一个主体使用各 App，不在 B 站插件里另启动一个有独立人格、日报任务和发送权的 agent。
- 只有实际送达或主动读取的内容属于经历；后台收件箱、未读 QQ 正文、未打开的视频全文不能进入摘要、记忆或上下文。
- 点赞、评论、收藏和分享均由模型显式选择，不按喜爱分数自动执行，不要求每天刷、每天分享或写日报。没有想看的可以退出。
- 分享使用 B 站提供的原生分享资料或普通链接，不自行制作分享卡片、不套固定推荐模板、不强制附带感想。
- 普通私聊继续原独立聊天链路，管理员任务继续通过已核验入口进入主体。
- 既有 QQ 通知概率、空引用/@过滤、名字规则、preamble 限次、回复处理、原记忆与关系机制保留，除本计划明确的新入口外不自行改动。

## 2. 实施前核对与技术原则

目前的事实是：DSH 已复用持久会话；`agent.run()` 表示一个有限的运行回合；`world_finish` 结束当前回合；World 按通知和原生提醒调起主体。不是缺少 DSH 历史，而是尚未有独立的、可持久化的生活活动语义。

实施前重点读取：

- `host.py`、`dsh_runtime.py`、`dsh/world.mjs`：唤醒、步数、结束、持久会话与扩展点。
- `dsh/context.mjs`、`context_log.py`、`experience.py`：实际输入、合法历史替换、压缩、经历回看。
- `store.py`、`kernel.py`、`toolbox.py`、`contracts.py`、`process.py`：账本、工具、App协议与进程隔离。
- `apps/qq.py`、`qq_preamble.py`、`group_chat.py`、`private_inbox.py`、`images.py`：已读、聊天与图片、私聊边界。
- `dsh/capabilities.mjs` 与实际固定 SDK：提醒的 Session 绑定、恢复与交付。

优先复用已安装的官方 `deepseek-harness-sdk==0.2.1rc2`。上游最新文档仅供设计参考，具体 API 必须对固定版本做实际集成验证，不凭文档推测已经支持。

继续让 DSH 管理模型与工具循环、会话持久化和压缩事务；World 维护业务活动和事件路由。不另引入 LangGraph/Temporal 全套依赖，不复制新的模型循环或第二套持久提醒系统。

### 第一项技术验证：活动历史能否安全退出模型输入

优先路线是保留同一个 DSH Session，以合法的历史投影/替换或压缩接口，在安全边界将已结束活动收为简述，并将过旧简述移出模型可见历史，完整日志保留。

必须先用真实 SDK、合成模型验证以下闭环，才能按此路线开发：

1. 完成两段活动并保存原始经历。
2. 下一段输入只包含近期简述，不再带两段活动的原始全文。
3. 历史里的工具调用/结果配对、消息来源与模型回放合法。
4. 重启后保持相同可见历史，且可检索原始全文。
5. 原生提醒仍只交付给现有 World 主体，不激活旧的独立模型循环。

若固定 SDK 不能可靠完成该替换，形成具体失败记录，再选择按活动轮换 Session 的方案；先解决提醒归属、旧 Session 激活、日志索引和操作身份兼容，不直接把 `session_id` 换掉交付。不得手工改 DSH JSONL、篡改冻结请求或静默升级 SDK。

## 3. 活动、运行回合与持久状态

### 3.1 区分两个标识

- **运行回合**：一次实际 SDK `Session.run()` 及其模型/工具步骤，沿用现有日志和计费标识。
- **持续活动**：星回选择继续的一段事情，可能包含多个运行回合和多个 App。

保留既有 `activity_id` 的历史含义，新增如 `logical_activity_id` 的跨回合标识；实施时统一命名并记录映射，不直接更改旧字段语义。App协议可增加主机提供的可选元数据，不允许模型伪造可信活动 ID。

可选的最小持久记录：

| 字段 | 含义 |
| --- | --- |
| id、created、updated | 稳定标识与时间 |
| state | running / waiting / suspended / finished |
| resume_note | 主体实际留下的继续意图，可空，不由程序编造 |
| resource_refs | 已观察的消息、视频、工具结果等引用 |
| execution_ids | 关联的实际运行回合 |
| wait_conditions、expires_at | 明确的恢复条件和有效期 |
| archive_state、archive_ref | 归档进度及读取入口 |

活动不与 App 一一绑定。看视频途中分享到 QQ、聊完再回 B 站，都可以属于同一段活动。显示当前使用的 App 不意味着锁定只能使用它。

### 3.2 模型入口

工具名称暂定，实施时收敛为尽量少的接口：

- `world_activity`：查看或更新当前活动的继续信息、已观察资源，不要求每次工具调用后填写。
- `world_pause`：持久保存继续意图、声明等待事件或时间，并结束当前计算回合。
- `world_finish`：放下当前持续活动，结束计算，返回日程控制的空闲机会。
- `world_recall`：扩展已有入口，按活动查简述、搜索和读取全文。

普通无工具输出仍允许停止计算；没有显式暂停声明时，默认放下当前活动，避免永久挂着 running。不能要求每次结束生成一份日志或强制写“下一步”。

### 3.3 暂停与恢复

- 暂停必须有明确事件/时间条件；事件等待有有限有效期。等待不占线程、不空转调用模型、不轮询群正文。
- QQ 等待可订阅明确群的新消息，收到后仍只给来源、触发单条消息及定位；上下文由主体主动读。
- “群免打扰”和“主体临时选择关注该群”分开保存。关注是模型主动声明的临时订阅，不能仅凭最近打开过某个群自动创建。
- 对聊天后续的等待，到期无消息就静默取消并回空闲，不再请求模型确认，不自动续设，不转成提醒或长期待办。
- 取消、结束活动、App停止以及订阅到期时，解除相应关注。迟到事件去重，不恢复已结束的活动。
- 事件恢复只提供上次选择与本次实际变化，主体仍可放下，不提示其“必须完成旧任务”。
- 当前活动中到达的新通知先落盘，在工具完成后的安全边界呈现；不强行取消有副作用的在途调用。
- 保持单主体串行，合并已经排队的唤醒，不启动多个互不知情的星回。

### 3.4 额度、崩溃与行为限次

- 原有步数额度保留。额度耗尽属于 suspended，不冒充正常放下、成功或完成。
- 不无限即时自续。记录原因，回到可调度状态，下一次合法的日程机会/事件携带续接信息；不能因 suspended 把周期机会永久关掉。
- 重启只恢复状态，不重放点赞、评论、发送或收藏等写操作；未知回执继续保持 unknown。
- preamble 的“同一活动同一会话最多一次”需覆盖跨回合的持续活动，同时保留同目标消息的防重。审计既有活动字段映射，不能通过暂停/恢复/换回合增加次数。

## 4. 活动简述与完整经历档案

### 4.1 模型可见内容

正常输入由以下内容组成：

1. 原 system、人格原文及实际需要的工具说明。
2. 最新环境状态、日程、当前活动与精确的未决操作状态。
3. 最近 N 段已结束活动的简述，首版 N=10，可配置。
4. 当前活动实际需要的完整工具链，或恢复所需的续接片段及原文入口。
5. 新收到的实际事件，以及显式回看得到的资料。

退出常驻列表不删除磁盘档案。旧简述不再通过另一个“总摘要”无限累积回上下文。当前活动太长、或显式读取大量资料时，仍可使用 DSH 压缩兜底。

### 4.2 简述生成与校验

- 每份简述针对一个逻辑活动，以该活动的原始观察和动作生成，不拿旧简述反复总结。
- 用几句话记录经过、实际选择、结果、确有依据的继续意图及未知项，附活动和原文引用。
- 摘要调用为独立的只读整理调用，记录 `activity_summary` 用量；没有外部行动工具，不会调度主体去完成摘要中的事情。
- 只汇总已经送达或实际读取的内容，不能扫描各 App 的未读存档。
- 字段与来源引用校验沿用现有验证思路。摘要有误仍可回看原文，不能当作新增的事实权威或个人记忆。
- 实际写操作结果由原操作账本附上。未知结果不能被写成失败、成功或未发生，也不能因为摘要列表淘汰而丢失全局未决状态。
- 一段活动只有在日志归档和有效简述持久化成功后，才能退出完整可见历史。
- 归档/摘要失败时保留原历史，标记待整理并有限重试；允许临时超过 N，不通过直接截断满足数量要求，不把整理失败包装成成功。

### 4.3 文件与检索

建议使用 World 自有目录，例如：

```text
var/experience/
  index.sqlite3
  activities/<id>/
    summary.json
    events.jsonl
    manifest.json
```

目录是主体可通过经历工具访问的实际档案，不把整个运行目录授权给它。初版优先用 SQLite/全文检索与按活动读取，不为此引入新的向量数据库。

`world_recall` 增加活动 ID、时间、App、关键词、分页和全文读取入口。返回清楚的范围、来源及下一页，读取结果进入实际观察记录。可以跨当前活动检索早期经历。

“完整”是该主体实际经历的完整记录，不包含未送达通知、未读 QQ 正文、普通私聊后台历史、凭证、管理员调试请求快照或整个模型请求重复副本。运行诊断日志继续独立保存。实际工具返回的截断、缺失、失败与媒体状态原样保留，不能归档成假定完整的视频或聊天记录。

采用临时文件、原子替换和可核验清单；处理数据库索引与文件之间的崩溃窗口，支持幂等重建。旧活动档案的检索不得依赖它仍在最近 N 条列表里。

### 4.4 现有历史迁移

不把现有 SDK 回合机械等同于人类意义的一次活动。对无法可靠合并的旧记录，保留为“旧环境运行记录”并注明边界。

先备份，再在副本中按已有观察/动作归档。未读 App 存档不参与迁移；不凭日志里出现某个 ID 就认定主体读过对应正文。核对记录数量、引用和写操作回执，做预览后再按已验证的同一方案迁入新格式。

原 Session 和原始账本保留，迁移可重复执行且不产生任何对外动作。新版本启动失败可以退回旧运行方式，不能用删除历史来恢复服务。

## 5. 日程唤醒、全群免打扰与环境概况

### 5.1 空闲周期

沿用用户认可的公式，value 使用原 ScheduleService 的有效 `talk_value`，原服务已限定到 0–100：

```text
value <= 5：睡眠，关闭周期唤醒
value > 5：间隔秒数 = 20 + 280 × (1 - value / 100)²
```

举例：85≈26秒，70≈45秒，50=90秒，20≈199秒，5关闭。

- 只在空闲/可调度的暂停状态计算周期机会，正常活动执行中不另开周期回合。
- 从上一活动放下或运行额度暂停后的调度基准计算，不能每次轮询都重置倒计时。执行中错过的心跳不补发、不堆积。
- 日程时段或 override 变化时重新计算；用单调时钟度量间隔，按 Asia/Shanghai 的日程状态解释时段，避免系统时钟回拨产生连发。
- 进入睡眠取消未触发的周期机会；不强制中断正在执行的操作。继续轻量检查日程，清醒后恢复安排，不用模型维持睡眠状态。
- 管理员请求与原生自设提醒保持独立。群 @/回复遵守原来的睡眠时通知规则；不借此修改原 `should_plan` 或概率参数。
- 现有固定 `--idle-seconds` 与新日程模式互斥且可明确回退，不允许两个周期器同时运行。新模式通过现有 command 启动，无需另开一个机器人。

### 5.2 QQ 设置及已读语义

首轮试运行将已知群普通消息设为免打扰，新增群也默认免打扰；提供设置入口，星回以后仍能主动调整，不把全群静音写成不可更改的策略。真实 @/回复带内容保留原例外，空引用/@仍不通知。

用户已明确：打开某页后，更早未展示的消息也算已读是正确语义。保留当前已读位置做法，不改逐条精确已读。

`world_open`、直接 `read_messages` 都必须推进同一已读位置；只收到通知、读取会话列表或查看未读数不算读过正文。免打扰不阻止存档、计数与主动阅读。

### 5.3 可自动提供的环境概况

每次实际开始决策时提供群名、会话 ID、未读数、免打扰状态及概况更新时间，帮助主体选择打开哪一群；不要求它每次打开 QQ。

新增一个严格限定的 App 环境元数据投影契约，由 App 自己发布、Kernel 缓存。它与现有供管理员查看的 `dashboard_state` 分开，不能把认知详情或最后一条消息摘要直接复用为主体概况。QQ 私有库仍由 QQ 拥有，Kernel 不直连读取。

不自动附加最近正文、话题总结、图片描述或私聊内容。元数据过期时标明时间，App忙碌或故障时返回未知/旧投影，不拖住其他 App或主体。

## 6. Bilibili App

### 6.1 复用与隔离

优先调查并复用 `c1overzz/dsh-bili-scroll` 的 B站工具/MCP 后端，再参考 `CZX2244/dsh-bilibili` 的视频读取与按时间取帧、`moxingovo/dsh-bilibili` 的工具拆分。

这些是 2026-10-28 的调查入口，实施时锁定实际 commit/release、依赖与许可证，建立可复现安装。不能用“插件已安装”代替真实能力验证，也不能假定某个后端已实现点赞或取消收藏。

复用能力层，省去该插件自身的定时值班、独立 headless agent、日报、强制筛选和人设提示。沿 World App协议暴露能力，独立连接、账号、缓存、依赖环境和故障隔离，不要求启动 DSH Web profile。

原生 DSH SDK仍是主体运行器。新增 App不得导入 QQ内部实现或修改主体循环的应用专属分支。

### 6.2 功能清单

| 能力 | 必须交付的行为 |
| --- | --- |
| 账号 | 扫码登录、状态检查、退出；凭证只保存在私有本地配置，不通过聊天传 Cookie |
| 浏览 | 当前账号推荐流、刷新/分页、视频信息、已有浏览记录 |
| 搜索 | 关键词、排序及分页；主体自行决定搜索什么 |
| 阅读 | 字幕与时间戳、封面、指定时间画面帧、评论与必要的楼中楼 |
| 无字幕 | 明确无字幕/需登录；可选 ASR 后端，不把摘要伪装成字幕原文 |
| 点赞 | 显式设为已赞/取消及可查询结果，避免用 toggle 导致重试反转 |
| 评论 | 发评论、回复评论及平台回执；保留实际评论 ID |
| 收藏 | 读取收藏夹、加入/移除及可查询状态 |
| 分享资料 | 返回 B站自身提供的分享信息或规范视频链接，可附已有时间点；不自制卡片 |

浏览结果是候选元数据，不意味着看过全文。读取字幕、画面、评论分别记录实际范围；片段、首个分P、截断和无法获取都要标明，不能说成已经看完整个视频。

将视频帧接到可复用图片组件；当前主体仍是文本路由，视觉结果来自独立视觉模型，不能仅返回图片块就宣称主体已看见。原 QQ 初步视觉 prompt 不修改。

初版可仅完成快速字幕/故事板路径并如实说明 ASR 不可用；若接入慢转写，返回 job_id，用完成事件和活动暂停恢复，不在 120 秒 App调用里无限等待，也不为每个任务启动另一名人格 agent。

站内互动自由由主体选择，不加每日配额、兴趣阈值、每看必赞或固定评论模板作为行为脚本。接口节流、平台限流处理和资源上限属于实际工具条件，需在结果中明确，不伪装成星回主动选择。

### 6.3 QQ 分享

使用明确的跨 App动作：主体取得 B站分享资料/已观察链接后，再调用 QQ 公开分享工具。B站 App不得直接调用 QQ发信、读取 QQ库或自行决定接收人。

QQ 分享工具应支持：

- 已知群，或已配置管理员私聊。
- 只发链接/原生分享资料，也可附主体自己写的文字；不要求推荐理由或总结。
- 可选引用已观察消息，也允许独立发起。不能为了满足旧 `reply_admin` 的输入而伪造一条管理员任务消息。
- 对其他普通私聊不开放这条任务/主动分享入口，保留现有分流边界。
- 通用链接资源格式，便于未来网页等 App复用；没有可验证的原生分享资料时发普通链接，不自己拼标题封面卡片。
- QQ 的口吻继续遵守原群聊/对应场景要求，不另加 LLM重写正文。没有真实被回复对象时，不编造关系增量或引用目标。

分享台账记录资源、已选目标、实际 QQ消息 ID、附言及回执，后续引用能够找回原视频和主体已看过的内容。发送重试防重，但同一视频不永久禁止再次分享；新的主动分享意图与同一操作的重试必须区分。

点赞、收藏、评论与分享的写入前落盘及 unknown 处理沿用 World原则。无外部幂等能力时不宣称严格恰好一次，不因超时换 ID重发。卡片/链接发送结果未知时不得自动换一种形式再发一次。

## 7. 分阶段实施与验收

| 阶段 | 交付 | 关键验收 |
| --- | --- | --- |
| P0 基线与 SDK验证 | 读取实际源码，固定兼容边界；完成活动历史替换的真实 SDK实验 | 原代码字节未变；已结束活动全文能安全退出实际请求；重启、工具配对、提醒归属通过 |
| P1 活动与事件 | 持久活动记录、回合映射、暂停/结束、临时订阅和恢复 | 暂停无模型轮询；到期静默放下；重复/迟到事件不重复恢复；跨回合 preamble 限次仍成立 |
| P2 经历上下文 | 活动归档、带来源简述、最近10项、按需检索；旧历史迁移预览 | 使用实际模型请求确认旧原文不常驻；更早全文仍可查；摘要失败/重启不丢历史或操作状态 |
| P3 日程与 QQ | 公式、睡眠、全群普通消息免打扰、群未读概况 | value=5不周期调用模型；活跃时公式正确；活动中不排心跳；通知打开同样推进已读；概况不泄漏正文 |
| P4 B站读取 | 锁定后端、独立 App、登录、推荐/搜索/阅读与图片适配 | 真实 SDK通过合成后端取得字幕和帧观察；无字幕等故障不伪造；QQ与其他 App不受 B站崩溃影响 |
| P5 互动与分享 | 点赞/评论/收藏、QQ原生分享或链接、写回执与防重 | 合成平台验证副作用仅一次；评论和 QQ消息 ID可追溯；可主动给管理员/群分享；不自制卡片 |
| P6 迁移与试运行 | 备份、验证后迁移、更新现有 command与配置、Web活动状态和回退 | 原生提醒不丢失/不激活旧主体；实际反向 WS连接恢复；功能开关可单独回退；运行版本和未验证项如实记录 |

阶段依赖：P0 → P1 → P2 → P3；B站后端可先做独立能力验证，但正式接入依赖前三项活动和上下文契约；P4 → P5 → P6。先修通用活动机制，再把 B站放进同一主体生活，避免各 App自行发展一套循环。

每阶段写实现与测试结果，不每完成一个可逆开发步骤就重新请求继续。遇到真正的原保护边界冲突、缺失账号授权或必须由人扫码的步骤，说明具体缺项；不把普通技术选择变成审批。

## 8. 必须覆盖的集成场景

1. 空闲 → 按日程唤醒 → 看群未读概况 → 自己选择不行动 → 结束。
2. 主动读免打扰群 → 回复 → 主动短期关注 → 新消息到来 → 选择继续阅读；无后续则到期静默放下。
3. 阅读视频 → 看评论/帧 → 点赞或收藏 → 自主分享给管理员或群 → 收到引用后找回原视频 → 可继续，也可退出。
4. 浏览期间跨过多个周期点，没有额外的“要不要换 App”模型回合；必要通知在安全边界送达，不重放在途写入。
5. 结束11段活动：实际请求只常驻最近10条简述，不保留第1段原文或另一份累积总摘要；仍能主动检索第1段全文。
6. 长活动跨回合与重启仍可续接；额度耗尽不被归为完成，未决写操作不被简述丢掉。
7. 未读 QQ里放入合成秘密标记：只有未读计数变化，活动简述、档案和模型输入均不包含标记；明确读取后才出现。
8. 摘要非法引用/生成失败/文件只写一半/索引写入中断：保留原记录，重启可恢复，没有隐藏的数据删除。
9. 发送已成功但回执丢失：unknown 保持不重发；同操作重试不重复，明确的新分享意图仍可执行。
10. 停止/移除 B站 App：不影响 QQ、笔记、提醒和已有经历回看；活动中的资源不可用时如实返回。
11. 原 prompt、普通私聊、群聊通知过滤、照片理解、一次 preamble、原聊天与计费/回填等现有功能回归。

优先用真实安装的 SDK/原生进程、合成模型 HTTP/SSE、合成 B站服务、测试反向 WS及受控时钟，不能仅写 mock单元测试后宣称 SDK集成完成。不用真实群发、真实评论或点赞测试替代合成验证。

## 9. 部署、回退与交付

- 开始前核对当前运行方式与实际配置，保留并行维护者的更改，禁止重置整个工作区。
- 单独备份 World、QQ、DSH持久目录和配置，备份仍为私有数据，不进入提交。
- 先在副本完成迁移和恢复；正式迁移与加载更新选空闲安全边界，使用现有 command，同一 QQ账号只运行一个自动主体。
- 保留活动上下文、日程周期和 B站 App的独立开关。回退时不丢弃新增日志、不重新执行旧外部动作，也不让旧 Session自行接管发送。
- Web增加活动状态、暂停条件及到期、下次周期机会、睡眠状态、归档失败与 B站登录/工具可用性。管理页面读取不算主体经历，不偷偷标已读。
- 完整回归记录现有已知失败，不修改原测试/基线掩盖。规划时最近已记录的结果为293通过、1项既有原 prompt断言失败；实施时重新核实，不将该数字当作新测试结果。
- 验证真实提供商或真实 B站只读接口时单独记录范围；登录必须由用户完成扫码。上线后显式工具选择可执行用户已要求的站内互动和 QQ分享，开发者不手工伪造星回兴趣进行试发。
- 每项交付报告说明做了什么、复用了什么、原行为哪里改变、怎样验证、哪些仍未验证。任何阶段不得把未完成 App或原生图片能力宣称已可用。

# 环境决策层的信息需求

日期：2026-10-28。

这是讨论与实现依据。环境提示与第一批动态事实已于本日接入，全文和接线见 [ENVIRONMENT_PROMPT.md](ENVIRONMENT_PROMPT.md)。原聊天 prompt、人格原文与认知算法保持原样；未完成的能力不能写成星回已经拥有的能力。

## 目标

环境让星回理解自己的身份、所处世界、可用能力、当前经历与行动后果。是否聊天、阅读、搜索、记录或结束活动，由星回选择。无需为一次唤醒虚构任务，也不加入每日社交、成长、探索或效率目标。

普通任务型 Agent 的持久执行、交付、进度汇报规则有各自产品前提，不能直接移植为星回的生活要求。保留工具契约与事实边界；生活选择不由提示词替代。

## 参考来源与取舍

以下来自官方公开文档与开源实现，不使用网上泄露或转述的完整系统提示词。OpenAI 与 Claude 部分参考官方开发文档，不声称已取得其产品完整内部提示词。

| 来源 | 已核对的做法 | 对星回的适用点 |
| --- | --- | --- |
| [OpenAI Agents 官方文档](https://developers.openai.com/api/docs/guides/agents/define-agents) | 指令、工具与程序本地上下文分别配置；程序持有的信息不会自动成为模型可见的信息 | 明确每种事实通过何种渠道交给模型，避免把数据库里存在等同于星回知道 |
| [Claude Agent SDK 官方文档](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts) | 自定义身份/界面可以使用自定义提示；会话还可能收到系统提示之外的上下文与提醒 | 检查实际完整请求，不能只审查一个 system 字符串；明确运行时事件与人类消息的来源 |
| [Anthropic 上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | 提示明确而不过度规定步骤；信息按需获取，避免上下文堆积 | 环境协议给足事实与语义，应用正文与知识按选择读取 |
| [Gemini CLI PromptProvider 源码](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/prompts/promptProvider.ts) | 根据实际配置、工具名称、Skill 与模式组装提示片段 | 提示中的能力与当前工具、配置同步，缺失的能力不伪装存在 |
| [DSH system-prompt 官方实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/system-prompt/README.md) | 分离身份/人格、提示片段、动态上下文与工具 schema，并按作用域组装 | World 采用可追溯的模块贡献，应用接入不要求重写主体提示 |

下面的需求是针对星回的设计判断，不是上述项目的原文或共同强制规范。

## 一、稳定的身份与环境说明

### 1. 我是谁

- 星回的身份与人格应来自用户认可的原文和配置，保留来源，不另编一份替代人格。
- 环境选择与原聊天属于同一产品中的能力，不能让外层长期只剩一个名字、聊天后端才具有人格。
- 这是一项待解决的接入设计：不能直接复制整段原聊天 prompt、添加包装或改动其输入，绕过原兼容约束。
- 原有情绪、关系、记忆算法不在环境提示中重新定义，也不通过新文字覆盖。

当前：环境入口已原样附加显式配置的人格 JSON；完整共享认知仍未完成。

### 2. 我在哪里，能如何行动

- World 提供应用、工具与观察记录；QQ 是一个应用。
- 可以发现应用、展开能力、主动读取、执行操作、保持安静或结束活动。
- 没有通知也可以主动打开应用；没有待完成任务也可以结束。
- 普通模型文字目前只记录于环境历史，不会自动变成 QQ 消息或任何其他对外内容。
- 浏览器、搜索等尚未安装的能力，不写入当前能力说明。

当前：稳定提示已说明环境、按需发现和实际可用性的区别，应用说明仍依赖 Manifest 与工具结果。

### 3. 通知、读取与记忆分别意味着什么

- 收到消息是 App 的事实；收到通知只获得来源和触发单条消息。
- 通知送达、主动读取上下文、App 的已读位置、形成个人记忆是不同状态。
- 忽略通知不等于否定消息内容、不喜欢发信人或一次原 Planner 的 no_reply。
- 未读内容不会因为它存在于数据库、管理员网页、日志、后台摘要或学习结果里就成为已知信息。
- 通知与正文是带来源的观察，不因为其文本提出要求而获得环境规则或工具权限。

当前：通知/观察/已读已有独立记录，忽略通知不伪造原 no_reply；新版提示已说明各状态的区别。

### 4. 行动、结果与结束

- 工具定义应明确目标、读写效果、必要条件、返回含义及历史覆盖范围。
- 计划、已发起、成功、失败、结果未知必须分别表达；以实际回执为准。
- 对外写操作结果未知时不能盲目重发；重启不等于先前操作没发生。
- 结束活动表示当前不再继续调用模型，之后由实际启用的通知、提醒等机制再次唤醒。
- 设置提醒不代表已经完成相关事情；提醒到期也不是必须执行的命令。
- 一轮调用有资源上限；预算耗尽与自愿结束不同，不能编造“我已经做完”。

当前：操作回执、unknown 与基本恢复已实现；一轮默认最多 20 步。新版已提供结束/中断语义、每次决策的剩余额度和上轮实际状态。

## 二、每次唤醒与活动中需要的真实状态

这些是动态事实，不宜硬编码为永久 system 文本。角色、字段和传输方式由具体模型适配，来源语义必须保留。

| 信息 | 应包含的事实 | 当前状态 |
| --- | --- | --- |
| 时间 | 可读本地时间、时区；必要时补充距上轮活动的间隔 | 已提供 Unix 时间、可读本地时间与时区；上轮结束时间可用，未单独计算间隔 |
| 唤醒来源 | 通知、自设提醒、手动启动、已启用的周期事件或恢复；可以同时有多个原因 | 已传递实际唤醒原因，可合并多种原因；恢复批次会注明 recovery |
| 通知 | 通知 ID、App、来源、触发单条消息；区分新增与以前已送达 | 仍最多 100 条，新版附 new_ids/earlier_ids 区分，通知正文字段不变 |
| 活动连续性 | 自己此前选择做什么、最后确认的进展、仍未解决的操作、可定位的观察引用 | 已有持久历史、工具批次恢复及上轮开始/结束/状态/步数；没有独立长期意图记录 |
| 当前能力 | 已注册应用、能否运行、连接状况、操作是否启用、必要条件是否满足 | 每步提供应用目录；持续 serve 提供 QQ 连接与参与开关。工具仍可能因更具体的条件不可用，需看回执 |
| 当前观察 | 实际读到的片段、来源、时间、分页/截断、快照或版本范围 | QQ 有快照/分页；尚无所有 App 通用的观察来源结构 |
| 本轮限制 | 实际剩余调用额度、被拒绝或不可用的能力，以及会影响选择的原因 | 已提供剩余调用额度和已知 QQ 状态；更具体的拒绝原因仍通过工具结果得知 |

唤醒原因属于运行时事件，不应伪装成管理员对星回下达的新任务。恢复只描述事实，不自动创建“必须继续”的目标。不得将模型隐藏推理当作持久活动状态；只保存显式选择与可验证进展。

## 三、按需获取的自我状态、知识与应用内容

### 1. 日程、情绪与关系

- 能知道原日程服务实际生效的状态，附来源和时效；沿用原文与规则，不把时段改写为强制作息命令。
- 如提供情绪或关系，必须取自原服务的实际状态；不另算一套、不因模型查看而触发衰减或关系变化。
- 个人已形成的认知与未读群记录应继续隔离；不能扫描所有群消息给环境补全“社交世界”。
- 管理员页面能显示，不意味着已经提供给星回；需要单独定义模型可见的只读投影或查询接口。

当前：原日程已用于通知概率和原聊天，Web 能显示；外层已收到原日程当前状态，暂无模型操作日程的工具。原情绪、关系按聊天后端惰性使用，尚未接通外层统一认知。

### 2. 记忆与笔记

- 当前上下文、自己保存的笔记、原长期记忆和 App 原始存档需要清楚区分。
- 告知哪些会持久保存、如何定位与回顾；不能承诺上下文中出现过就永久记得。
- 长期记忆的来源、形成与检索仍遵守原设计和观察边界，不能默认自动吸收所有 App 内容。
- 如使用压缩摘要，应保留来源引用、时间和不确定性，不补写没有经历过的事实。

当前：Notes 与环境历史持久化可用；原长期记忆没有作为环境工具提供。没有环境活动摘要与按 token 的上下文管理，不能仅以提示词声称这些能力存在。

### 3. 应用工具与 Skill

- 目录提供简洁的能力入口；具体操作的说明、参数和副作用由对应 App 提供。
- 工具 schema 与实际可执行能力同步；说明过期时以当前事实和回执为准。
- Skill 是按需阅读的知识，不是安装后立即注入的整套行为要求，也不自动授予新工具权限。
- App 的使用说明只能描述该 App，不能覆盖星回的身份、其他 App 的状态或环境规则。
- Browser 等未来 App 的搜索摘要、网页正文、图片、分页及加载状态应分别说明，避免把结果列表当作全文。

当前：工具按需展开、配置目录内 Skill 读取已有；通用 App 提示片段注册、安装与版本管理未实现。

## 四、保留在程序里的内容

数据库、API Key、进程号、内部 IPC 路径、网络认证细节、管理员调试日志，不应默认放入模型上下文。只有影响当前决策的产品事实需要暴露，例如“QQ 未连接”或“发送未启用”。

权限、数据隔离、回执校验、通知过滤与重复发送保护必须由程序执行。提示词负责解释语义，不能充当唯一的约束实现。

环境不预设每日聊天量、探索频率、兴趣培养、成长目标或活跃程度；也不照搬编码助手的持续交付、每步汇报和强制规划规则。

## 五、建议的组织方式与优先级

输入分为五类：受保护身份原文的接入、稳定环境协议、带来源的动态事件与自我状态、实际工具 schema/按需说明、已经观察到的历史与结果。每段应能追溯到文件/配置、App 或运行时事实，避免不同模块重复、冲突或互相覆盖。

第一批已接入原人格、时间与唤醒来源、上轮实际状态及部分能力状态。接下来仍需设计长期活动意图、原认知的只读访问与通用观察来源结构。最后再扩展新的 App 提示贡献与知识加载机制。不能只加长 system 文本，跳过这些程序能力。

审阅时至少检查：

1. 只有通知时，模型没有得到未读正文；免打扰群也没有摘要/学习旁路。
2. 没有新任务时允许结束；通知不强制触发聊天、搜索或记笔记。
3. 工具不可用或历史不完整时得到真实说明，不编造成功或完整知识。
4. 写操作结果未知时不会仅因重启或提示变化而重复执行。
5. 旧观察具有时间与范围，不能在没有刷新时被当作最新页面或群上下文。
6. 原 prompt、原聊天请求组织与模型参数保持兼容；新增信息只进入明确的环境决策入口。
7. 没有读取的内容不能经活动摘要、记忆检索或管理员资料间接进入认知。

# 图片观察与按问题细看

2026-10-28，QQ 0.5.0。用户授权保留原聊天视觉设计，按 agent 的主动观察方式接入，并增加独立的细看能力。

## 使用流程

收到 QQ 图片消息时只保存原始事件，不下载、不识别、不学习。通知仍只有来源和触发的单条消息。主体调用 `read_messages` 或打开通知后，才处理这份固定快照范围内的图片；之后到达的消息不会混入。

打开时调用原 `VisionService.describe`，沿用原 `vision_prompt()`、视觉模型配置、分类校验和缓存，没有更改受保护文件。原方法是 30 字内的初步描述，适合聊天快速理解，不保证覆盖图片中的全部细节。图片描述进入当前观察快照和基于它生成的聊天上下文，不回写原始消息，不自动调用表情收藏或长期记忆提取。

每条消息增加 `media`：图片包含从 1 开始的 `image_index`、理解状态、初步描述、原分类字段和是否已保留原图。状态区分 `understood`、`failed`、`unavailable`、`deferred`、`not_understood`。失败会在聊天上下文中明确显示未知占位，不能把失败降级文本当作识别成功。`requires_media` 保留为是否存在未知媒体的提示；在默认主体回复模式中不再作为发送门槛，preamble 也不受无关图片阻断。显式 legacy 参与仍保留未理解媒体保护。

需要进一步读取文字、核对截图或观察细节时，主体可调用：

```json
{
  "observation_id": "实际取得的观察 ID",
  "message_id": "该快照中的消息 ID",
  "image_index": 1,
  "question": "本次需要观察的具体问题"
}
```

工具为 `qq.view_image`（DSH 展开名 `qq__view_image`）。图片序号在单条消息内计数，省略时为 1；不接受任意 URL 或本地文件路径。调用前验证消息和图片确实属于指定快照，不能借此打开快照外的新消息或其他会话。细看结果只作为本次工具观察返回，不覆盖初步描述、分类或发送账本，也不发送消息。

## 后端与持久化

当前主体路由没有声明图片输入，实际看图由 `.env` 中原有的 `ASTCHO_VISION_MODEL/API_KEY/BASE_URL` 指向的独立视觉模型执行。细看使用新环境专属的 `images.DETAIL_PROMPT`，按具体问题调用原 `LLMService.raw_completion`，保留实际用量采集。没有将文本主体伪装成多模态模型，也没有更换其会话或开启 DSH 文件/命令工具。

`images.ImageReader` 不依赖 QQ、Kernel 或 DSH，其他 App 可以复用该组件并持有自己的资源目录。QQ 的定位与观察校验放在独立的 `qq_media.py`，不要求其他 App 访问 QQ 数据库。

原图只在主动观察时保存到 App 自己的 `images/` 目录，文件按内容 SHA-256 去重，来源索引使用 URL 哈希，文件权限为 0600。细看复用保留的字节，因此同一来源的链接过期、App 重启后仍能继续提问。成功描述与原图留存是两种独立状态：历史分类缓存仍可能可用，而原图下载已失败，此时会返回 `retained: false`。没有原图且远端链接已失效时如实失败。

为保持原服务不变，首次打开时原图留存和原服务识别各下载一次；后续原图读取和初步描述分别复用自己的缓存，换问题细看仍重新调用视觉模型。没有增加总输入 token 上限或会话裁剪。

单份阅读的媒体处理最多 60 秒，最多并发 3 张，单张初步处理最多 40 秒；超时部分逐条标记，已取得的文本和描述仍返回。单次细看最多 80 秒，适配已有 120 秒 App 工具期限。原图留存单张上限 20 MiB，支持 PNG/JPEG/GIF/WebP；这些是单次资源处理限制。视频、语音和转发当前在新观察适配器中明确标记未理解，未冒充已接入对应服务。

## 验证

`tests/test_qq_images.py` 覆盖真实本机图片 HTTP、原 VisionService/LLMService、原 prompt 一致性、缓存、失败重试、逐图失败隔离、未读范围、目标越界、来源缺失、阅读超时、资源限制，以及实际 Python SDK/原生 DSH 的初步阅读 → 提问细看 → 结束链路。主体收到的是文字结果，不包含图片 base64。

另用程序生成的 32×32 纯红图片验证本地实际配置的视觉接口：初步描述和细看均成功，细看回答红色。未读取私人图片用于该测试，未向真实 QQ 发送测试消息。

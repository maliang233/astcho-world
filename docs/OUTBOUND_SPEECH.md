# 对外说话规则

2026-10-29，用户要求所有面向人的发言都遵守原聊天风格和表达规则。此前完整原群聊要求只随 QQ 的 `reply_context` 返回，管理员主体私聊、主动分享与 B站评论缺少共同的风格入口。

## 规则来源与范围

`speech.py` 调用受字节保护的 `astcho.prompts` 构建函数，仅提取固定说话段：

- 通用部分来自原普通 `reply_prompt` 的“说话方式”段，逐字保留非群聊专属的完整行，并复用原“不懂就问……”原文。原群聊专属行保留在完整群聊说话段中。
- QQ群聊保留完整原“说话方式”段。实际读取群聊后的 `reply_context` 仍按原 `reasoning_enabled` 选择普通或推理 Replyer；所选原要求及对象的记忆、情绪、关系、表达提示继续决定本次群聊的具体表达。现在同样适用于该群行动前说明和分享附言。
- QQ私聊复用完整原 `private_reply_prompt` 的“说话方式”段。管理员任务结果、澄清、私聊行动前说明和私聊分享附言同样遵守它，无需先读取群聊。

固定原文通过 `environment_prompt()` 加入两种主体运行器的 system prompt，每次活动与后续工具步骤都可获得；不复制原聊天任务、JSON输出指令、虚构对象/记忆/消息或动态时钟。人格原文继续按原流程附加。QQ工具描述和B站评论描述指向这一共同来源，新增App也遵守同一规范，无需依赖QQ内部实现。

适用的是准备发给人的正文，包括聊天、说明、结果、附言和站内评论。纯链接仍可直接分享，不强制附言。笔记、内部推理、`audience_reason` 等内部参数、归档与独立交付文件不因此改写成短聊天。新增规范不让普通主体输出自动转发，不强制开口，也不改变分享保护、评论克制、身份核验、一次 preamble、未知回执和重试规则。

原 `src/astcho/prompts.py`、原ChatService、普通非管理员私聊完整链路与人格文件不改。没有增加第二次风格生成/审查模型调用，也不在发送时替换措辞、删除格式、截短或强加固定颜文字。风格通过原规则约束主体选择，不能将通过接线测试表述为模型永不偏离。

## 验证

固定段逐字比较；只提取固定规则、不注入虚构对话；无需QQ观察也能获得私聊/通用要求；原保护基线不变。真实安装的DSH SDK配合本地合成模型验证无QQ App的笔记活动及同Session恢复、管理员私聊经测试反向WS回复、B站评论与分享连续工具链的实际system消息均含同一规则。原群聊适配、普通私聊隔离、preamble限次、分享去重等相关回归同时运行。测试不调用真实模型、不向真实QQ或B站试发；真实口吻需后续使用观察。

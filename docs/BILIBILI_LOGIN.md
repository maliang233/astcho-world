# Bilibili扫码登录

2026-10-29修复。当前App版本0.2.0。

## 根因与上次修复的不足

实际两次扫码后，SDK均报告DONE，但Credential中的session/CSRF为空。当前安装的bilibili-api-python 17.4.1只从成功响应URL的query中提取Cookie；新版WEB登录返回跨域票据，Cookie需跟随票据链接后从Set-Cookie读取。此前仅补了空凭证检查与保存前验证，没有修复获取凭证这一步，导致真实扫码仍失败。

该兼容问题在[public-clis/bilibili-cli的修复PR](https://github.com/public-clis/bilibili-cli/pull/27)已有报告。本实现未直接复制该补丁或修改已安装SDK，而是在Bilibili App内提供独立WEB登录适配器，其余浏览/互动仍使用原SDK。

## 当前流程

1. 管理员点击扫码登录，调用B站WEB二维码生成接口，在本地生成PNG。
2. 页面每2.5秒自动检查。分别显示等待扫码、已扫码待手机确认、凭证校验、已登录和二维码过期；可以立即检查、重新生成或取消。
3. 成功响应兼容旧URL参数与新跨域票据。仅访问HTTPS的Bilibili/Biligame域，校验每次跳转；带浏览器UA，分别解析响应头中的Cookie，兼容普通CookieJar不接收跨域Cookie的情况。未知扫码状态不会当成成功。
4. 成功二维码key会被消耗，因此获取到的票据、Cookie及待验证凭证先私有持久化。网络中断后继续票据兑换或账号验证，不重新轮询已成功的key。账号验证通过才原子保存正式credential.json，并以实际账号mid写入UID。
5. 页面刷新和App重启可恢复进行中的扫码。取消或完成清理临时状态及二维码；更换二维码后旧login_id的检查/取消不作用于新流程。失败不覆盖已有正式凭证。

二维码/临时状态文件权限0600，凭证、key、票据与refresh token不进入Web返回和普通日志。二维码图片及随机login_id供管理页面使用。网络错误不回显含票据或key的请求URL。账号管理控制不进入主体观察；状态/检查不反复写入带图片的App回执。登录验证不调用LLM或发送QQ/B站消息。

## Web交互与停止条件

二维码节点在实时刷新中保持连接，不因一次检查消失。账号面板显示可读状态和账号名，而不是直接展示原始JSON。只在对应App页面可见且确有待完成流程时自动检查；离页/隐藏、登录完成、过期或取消后停止。连续3次错误暂停自动检查并保留二维码，允许手动重试。不自动重新生成二维码或替管理员确认登录。

## 验证边界

测试覆盖新旧返回、跨域Set-Cookie/302、确认状态、过期、异常状态、外部跳转拒绝、密钥脱敏、一次性key不重用、票据中断恢复。独立B站运行环境使用真实Credential与二维码库，模拟完整扫码/验证中断/新App恢复/重新加载正式凭证/退出。Web控制逻辑验证自动检查不被实时刷新推迟、无并发重复、离页停止、错误限次及手动恢复。

独立合成服务通过实际浏览器验证二维码显示、自动经历待扫码/待确认并最终显示合成账号已登录，以及刷新后账号状态恢复。截图为合成账号，不代表真实手机授权已完成。真实扫码仍需用户在手机上确认。

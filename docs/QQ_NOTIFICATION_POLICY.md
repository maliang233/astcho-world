# QQ 通知与安静等待

2026-10-28，用户讨论后明确授权。QQ 0.4.0 将通知资格、读取消息和是否立即回应分开；普通私聊及管理员私聊分流不变。

## 群聊通知

| 情况 | 行为 |
| --- | --- |
| 只有引用、@和空白，无实际内容 | 不通知，包含真正引用/@星回的情况 |
| 仅一条名字，去掉首尾空白后等于已配置 bot_name | 不通知；这是单独呼名，不能额外包含引用/@等定位或媒体 |
| 普通正文提到名字 | 不再被识别成 direct，也不优先作为批次触发消息；按普通概率计算 |
| 有实际内容的真实@或引用星回 | 保留直接通知和免打扰例外 |
| 其他普通消息 | 保留原概率与日程、频率、情绪等参数 |

“有内容”结合正文、已存在的图片描述和原始 OneBot 消息段判断。引用原话、@参数或空白不算发送者添加了正文；图片、QQ 表情、语音、视频、合并转发、卡片等是实际内容，不能因为 `text` 为空而丢掉。数组和 CQ 字符串两种编码均识别。未完成媒体理解时仍保留原发送限制，不把结构识别当成已经理解图片。

`qq_notifications.NotificationAttention` 只替换 direct 判定，调用受保护原 `AttentionService.should_plan` 概率公式，没有拷贝或另写公式。被过滤的消息仍落 QQ 原始存档；不产生通知、不形成个人记忆、不提交 no_reply。一个批次末尾的空引用/@不会盖过前面有内容的触发消息。

## 显式读取

`read_messages` 的群聊消息增加 `empty_addressing` 与 `content_types`，仅表明实际消息结构。引用 ID、@方向、原话及内容仍保留。不把空引用统一翻译成无语、质疑或某种情绪，不自动删除或回复。

新环境的 Planner/普通 Replyer 提示适配，将静态说明中的“@/引用需要回复”限定为有实际内容的消息，空引用/@通常无需接话。替换只发生在原模板的静态规则段，用户正文、人格、记忆里的同样文字不会被替换。受保护模板和显式 legacy 群聊生成链路仍保持原样。

## 等后续可以放下

看到话可能尚未说完时，主体可以直接结束活动，保持安静；日后有正常通知，再决定是否关注。暂缓接话不等于一次 no_reply，不自动应用情绪/关系变化，不发占位消息或 preamble，不把这段对话变成欠下的任务。

默认不设提醒，不新建等待工具、轮询器或后台监视。确有必要时可以克制使用现有 DSH 原生提醒，同一段等待最多一次非重复回看；提前看到后续可取消，回看没有进展就结束，不延期、续设或转成周期提醒。该次数与克制要求是主体提示，未对通用提醒工具增加语义分类或程序硬限制，也不影响其他用途的正常提醒。

原有 2–5 秒入站聚合窗口保留，它与主体读完后选择暂缓不同。没有强制每条消息等待固定秒数，也不保证普通后续一定触发通知：等不到就算了。等待不会自动读取未读内容或跨活动保留一个必须完成的目标。

# 主体直接组织群聊回复

2026-10-28，用户讨论后明确授权实施。默认群聊改为一条 DSH 主体工具链：阅读 → 可选搜索、读取网页或其他行动 → 自己组织正文 → `qq.reply_group` → 查看实际回执。不再通过 `participate` 另调用原 Planner/Replyer。

## 信息与工具

- `read_messages` 仍建立固定观察快照；群聊增加默认回复对象的 `reply_context`。默认对象是快照内的锚定消息，否则为最近的可回复群友消息，不替主体作最终选择。
- `reply_context(observation_id, target_message_id)` 可读取同一快照内另一个群友对应的记忆、关系、情绪、日程、原表达提示和原格式上下文。不读取后来的消息，不调用 Planner/Replyer，不提交社交判断。
- `reply_group(observation_id, target_message_id, text, ...)` 发送主体准备的正文。可附原 Planner 的 `reason`、`excitement`、`shyness`、`affinity_score`、`should_meme` 和 `meme_query`，数值范围沿用原模型。正文校验沿用原 `ReplyPayload` 的 1000 字符上限；没有添加总输入 token 预算。
- `no_reply(observation_id, target_message_id, ...)` 是可选的明确社交判断，允许原范围内的情绪更新并调用原注意力状态更新。忽略通知、阅读、搜索或结束活动不会自动调用它。
- 对外只发送 `text`，主体普通输出、内部分析和工具返回不会自动转发。

记忆和关系依据已观察的对象读取；原记忆检索仍遵守原群聊/全局范围规则，不新增未读消息索引或摘要。首次打开可惰性初始化 QQ 自己的原版 Runtime；其他 App 不依赖它。QQ 0.5.0 已在主动读取时接入原图片理解，并提供按问题细看的 `view_image`；未理解媒体逐条标明，主体可以根据已知文本判断，不再因无关图片禁止整份快照回复。详见 [图片观察](QQ_IMAGES.md)。

## Prompt 迁移边界

原 `src/astcho/prompts.py` 没有编辑。新层 `group_prompt.py` 调用其函数，保持适用的原文，不重新撰写人设或口吻：

| 来源 | 迁移方式 |
| --- | --- |
| 原 Planner | 原消息格式说明、是否回复、配图规则、字段说明与群状态复用；移除独立 Planner 的“不能搜索或外部操作”限制、JSON 输出外壳与末尾输出指令；后续授权限定空引用/@的回复义务 |
| 普通 Replyer | 复用原文本，适配独立 JSON 输出约定与末尾输出指令；后续授权将静态@/引用必须回复规则限定为有实际内容的消息 |
| Reasoning Replyer | 按原 `reasoning_enabled` 选择，复用原完整文本，只替换独立 `thinking/reply` JSON 输出块 |
| 人格、记忆、关系、表达提示、情绪、日程 | 仍用原构建与服务。没有另一个 Planner 理由时保持空值，不补造理由 |
| 新输出约定 | 正文放进显式发送工具，内部分析不发出；可先用工具或选择不回复；本次群聊的要求作用于回复、行动前说明和分享附言 |

World 的环境提示明确限定群聊对象、状态和表达提示的场景作用域；聊天、引用与网页内容仍是观察资料。用户在2026-10-29进一步授权所有对人发言统一遵守原聊天风格：原模板中的通用说话原文和原私聊说话原文现在也在环境 system prompt 中提供，管理员任务的对外回答沿用私聊要求。笔记、内部分析与独立交付文件不套用聊天格式。动态人格、真实聊天和记忆不写入公开文档。详见 [对外说话规则](OUTBOUND_SPEECH.md)。

这是模型路径与输入组织的有意迁移；原文复用不等于真实聊天表现已经验证相同。原字段范围、后处理与兼容基线有自动验证，真实口吻与决策表现还需实际使用观察。

## 执行、状态和回执

原 `EmotionService.apply` 与 `AttentionService.update_after_planner` 在明确社交判断时执行一次，不在每次模型步骤执行。群情绪快照随 QQ 自己的注意力状态保存，继续使用原衰减算法；亲密度仍由原 SQLite 服务保存。

发送沿用原 `apply_typo`、`split_reply`、被 @/引用时引用目标，以及分段 0.8–2.0 秒间隔；配图选择和间隔沿用原服务。新发送工具的正文使用字面文本段，不能通过正文中的 CQ 字符串偷偷增加 @、图片或其他动作。实际送达的消息逐条保存；原记忆入队只在正文全部确认发送后执行，不在读取或失败的分段上自动学习。原记忆提取、可选配图选择仍可能使用各自的模型，这次移除的是重复的 Planner/Replyer 调用。

`reply_group`、`no_reply` 和兼容 `participate` 共用快照决定账本。同一快照只执行一次；相同决定重试返回既有回执，改正文、对象或动作返回 conflict。分段中断保留已确认部分，返回 unknown，不再自动重放；进程中断留下 running 时恢复读取为 unknown。不自动发送剩余部分或再次改变情绪。跨 QQ 业务库、原认知库与远端 QQ 之间没有分布式事务，崩溃后的未知影响仍如实保留，不能承诺回滚已发生的情绪或远端消息。

## 范围与回退

管理员私聊继续使用原已实现的主体任务入口和 `reply_admin`；非管理员私聊仍走独立原 Replyer，不获得新的群聊工具发送入口。

QQ 配置 `conversation.group_reply_mode` 默认为 `agent`。显式设为 `legacy` 并重启服务后，群聊恢复原 `participate` → Planner → Replyer，新的群聊发送/不回复工具返回 unavailable。切换不会清空任何会话、数据库或决定账本。不要并行运行两个自动发送实例。

## 可选的一次行动前说明

用户随后授权尝试 preamble，并明确聊天场景最多一次。QQ 0.3.0 增加 `preamble`：由主体选择是否先向正在回应的对象说明打算，再继续操作及答复。环境提示只说明适用情境与克制原则，不提供固定例句，不按耗时自动代发，也不要求每次搜索都说话。原群聊输出适配约定区分行动前说明和答复；受保护模板未编辑。

群聊传 `observation_id/target_message_id/text`；管理员私聊传 `chat_id/target_message_id/text`，两种定位方式二选一。群聊仍检查固定快照、群白名单与非自己消息；QQ 0.5.0 起未理解媒体不再阻断说明。私聊仍检查配置中的管理员及其真实来源消息。非管理员私聊未接入此工具。

每次调用最多一次 QQ send，字面文本、不拆成多个气泡、不配图、不再调用模型。它保存实际消息和回执，并更新真实发言时间，但不应用情绪/关系增量、不执行 Planner 注意力决定、不写长期记忆提取队列，也不占 `reply_group/no_reply` 的决定位置。不调用 `world_finish`，模型可以继续使用工具。

QQ 自己的持久 `preambles` 账本在发送前占位，按两个维度限制：同一活动的同一会话最多一次；同一会话的同一目标消息也最多一次。活动 ID 由 Kernel 从可信执行上下文提供，模型不能填写；前一项覆盖同一活动里的换目标/重读，后一项覆盖新快照、新操作 ID、后续唤醒和重启。相同请求返回旧回执；其他重复说明返回 `limit_reached`。失败/未知仍占次数，running 恢复按 unknown 返回，不重发。没有活动元数据的直接调用仍受目标消息维度限制。

提示还提醒不通过普通回复工具追加进度播报。程序限制针对明确的 preamble 工具；不另请分类模型审查普通答复是否暗含进度说明。社交表达是否克制、何时确有必要，仍需真实使用观察。

QQ 0.4.0 后续接入空引用/@及名字通知规则、可安静放下的等待提示，详见 [通知与安静等待](QQ_NOTIFICATION_POLICY.md)。等待默认不使用 preamble 或提醒。

## 2026-10-29：接话判断与近期参与事实

用户授权把接话判断放回整段交流中。在新环境 `prompts/actions.md` 加入讨论确认的说明：阅读本身可以是参与，能想到合适的话不代表想说，别人之间的对话可以继续、自己的话可以自然结束；接梗、闲聊、分享感受和主动开话题仍是自主选择，不要求每句话有用。原 Planner/Replyer 模板、表达风格、情绪增量和衰减算法不改。

QQ 0.6.3 的群聊 `read_messages` 增加 `participation`，只在实际打开后提供，不进入通知或ambient：

- `as_of` 与 `window_seconds=600` 给出观察时刻及统计窗口。
- `own.message_count` 统计该群该窗口内、本安装已知的自己消息，包括确认发送的气泡及收到的自身消息回显；`last_message_at` 是截至观察时刻已知的上次发言时间，可早于窗口。自己的已知动作可在本次显示范围之外，不需要重读。
- `observed_conversation` 的消息数、群友消息数/人数及上次自己发言后的群友消息数，只基于当前快照内、窗口内的已展示消息，明确可能不完整；不从App库汇总未展示群友记录。未知上次发言时，后续消息数为null，不假定为0。
- 每个QQ气泡单独计数，分段、图片、分享不伪称多个接话轮次。统计保存在同一快照；后来的消息和重启不会改写旧观察。对其他已观察对象调用 `reply_context` 时复用该快照的参与情况。旧快照没有此字段时保持原样，不从当前库补造旧统计。

统计是描述性事实，没有比例评分、次数上限、自动禁言、额外决策模型或定时检查。读取不自动发送、提交no_reply、增加情绪或写入记忆；非管理员私聊继续原路径。SDK集成只能验证信息实际进入请求及安静结束能力，接话是否更合适仍需后续真实聊天观察，不以合成模型的脚本输出宣称行为改善。

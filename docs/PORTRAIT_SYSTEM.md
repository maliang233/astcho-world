# 立绘、基础状态与活动联动

2026-10-29。人物参考见 [角色约束](design/CHARACTER_STYLE.md)，生成提示词见 [四张变体](design/portrait-variants-v1.json) 和 [睡眠修正版](design/portrait-sleep-v2-prompt.txt)。采用内置 imagegen，原安静立绘不覆盖。

## 信息与图片分开

`日程显示类别 + 当前运行回合的实际操作 → 展示状态 → 图片映射及回退 → 首页`。

- 基础：`base.idle` 安静待着、`base.class` 上课、`base.sleep` 睡眠。
- 活动：`activity.thinking` 思考、`activity.phone` 看手机、`activity.notes` 写笔记；后者与上课使用同一图片，但名称、来源和生命周期独立。
- 事件是发生记录，不是常驻姿态。收到通知不会自动成为看手机，管理员上传、预览、账号操作也不会成为主体经历。
- `activity.general` 是旧插件/未声明工具的通用回退，显示实际应用名与通用图片，不猜它在聊天还是看视频。

立绘选择在 World 的只读管理投影中完成，模型、工具输入和受保护 prompt 不接收显示元数据。GET 不调用应用、不修改通知送达或已读、不写展示状态。没有给模型另加选图工具或选图请求。

## 实际活动与退出

以 `activity.started` 划定当前运行回合，只读取其中已有的 `operation.started/finished` 与操作结果。运行阶段必须仍是 thinking/executing：进行中的操作显示对应活动；成功后的姿态最多延续清单声明的 `hold_seconds`（默认20、上限60），供紧接的思考使用。失败、取消、结果未知不延续；更新的具体动作会替换旧动作。空闲、结束、等待、挂起后回到基础状态，新回合不继承旧回合姿态。正在思考但没有适用具体动作时用思考图。

这是已有操作的可视化，不证明他一直盯着手机或真实播放着视频；B站的字幕/画面/资料读取使用具体文字说明。长期活动的 resume_note 仍在持续活动面板，不通过解析自由文本来猜姿态。

观察模式/未启动使用默认图并明确状态。Web 断线立即撤下活动姿态，显示连接中断；新状态图片先预载，约1.5秒稳定后切换，旧异步结果不可覆盖新状态。首页将立绘区域与数据区域分开更新；同图刷新时图片始终保持连接，不卸载后再插回，也不重复淡入。切换图片时复用预载并解码后的图片节点，避免 no-store 资源二次请求；过期预载回调按请求对象隔离。缺图和加载失败回退默认，选择依据默认折叠，可查看基础状态、操作ID、事件序号、过期时间和回退路径。

## 新增或修改日程

把显示类别附在时段自身，而不是匹配时间字符串、routine 名字或 mood_prompt：

```json
{"start":"09:00","end":"12:00","talk_value":20,
 "mood_prompt":"原日程文案原样保留",
 "presentation":{"base":"base.class"}}
```

更改时间、文案、每周安排时，保留该字段即可。新增时段没有字段会回退安静并显示“未分类”；设置 → 立绘与状态 → 日程基础状态可分类，不改时间、概率或原文。保存前校验整个日程版本，产生原文件备份，原子替换并重载。仅允许编辑当前项目或运行目录内的日程，外部/原项目文件只读。手工修改文件后的读取仍遵循原日程服务的重载/重启方式，不能通过浏览页面偷偷重载日程。

当前本地 `config/schedule.local.json` 已补显示类别，原时间、talk_value 和 mood_prompt 均保留。临时日程覆盖无明确显示类别时使用默认，避免从自由文案猜状态。

## 新 App 与活动

应用清单在已有 `dashboard` 中按已声明工具提供可选元数据：

```json
{"dashboard":{"version":1,"name":"日记","activities":{
 "write":{"kind":"activity.journal","label":"正在写日记",
          "fallback":"activity.notes","hold_seconds":20}
}}}
```

工具仍由原 `tools` 声明。显示元数据不增加工具参数，不进入 world_tools 返回的工具定义。旧清单继续兼容。语义标识稳定，不能把它写成图片文件名；新活动无需修改核心选择器，未有专属图时复用 fallback。fallback 必须避免环，运行时也有兜底。

不改插件清单也可以在设置页覆盖“应用工具 → 活动类型”。新类型通过“新增基础状态或活动”添加，选已有图片或指定回退。基础类别以 `base.` 开头、活动以 `activity.` 开头。元数据仅说明操作的表现，不能发布任意 HTML、JS 或读取额外 App 内容。

## 补图与替换

设置 → 立绘与状态：

1. 在“仅预览”选择目标状态，查看当前使用图片。
2. 上传透明 PNG（8 MiB以内、边长4096以内），自动加入该状态的草稿。
3. 检查预览后保存映射。上传本身不应用，预览也不更改星回状态。
4. 要恢复旧图，直接在“使用立绘”选择原资源再保存。按内容哈希留存上传文件，不覆盖旧图片；内置资源也保留。

无专属图片的状态显示回退提示，可按需逐步补齐。上下课/写笔记的共图关系只是两条映射，替换其中一条不会影响另一条。

制作时固定当前1312×1200透明画布、人物比例和底部桌沿位置，沿用同一原设定与已接受桌前图。不要每次从文字重建人物。四肢必须单独检查；用户指出的睡眠v1已移到 `docs/design/astcho-sleep-rejected-v1.png`，内置仅使用修正v2。

## API 与持久化

所有 API 要求同一管理员会话；POST 拒绝跨站。

- GET `/api/snapshot`：`presentation` 为当前展示状态及依据。
- GET `/api/settings`：`presentation` 包含状态/回退、图片库、工具映射与日程分类。
- GET `/api/presentation/assets/{id}`：只接受内置ID或内容哈希ID，不接受路径。
- POST `/api/presentation/assets`：原始PNG上传，校验体积、尺寸、PNG分块CRC与结束标记；浏览器上传前还校验图像可解码。
- POST `/api/presentation/config`：`revision`、`states`、`tools`；版本冲突拒绝，回退环及不存在资源拒绝。
- POST `/api/presentation/schedule`：日程 `revision` 和 `blocks[{routine,index,base}]`；只更新显示分类。

本地映射保存在 World state 的 `presentation_config`，自定义图片在运行目录 `presentation/upload-<sha256>.png`。备份时与 World 数据一起保存。映射保存即时生效，不重编译前端或 Mac 启动器。应用清单变更仍按原方式重启加载。
